# 한국어 관광지 상세페이지 표준

확정일: 2026-10-10. KoreaLiveNow의 한국 관광지 데이터·지도·상세페이지에 적용한다.

## 공개 범위

- 한국어판을 먼저 만든다. 확인된 장소·좌표·운영 정보가 없으면 빈 상태로 두고 일본 데이터나 가상 사실로 채우지 않는다.
- 한 장소에는 장소 ID와 정본 상세 URL 하나를 둔다. 기본 경로는 `/kr/attractions/{placeId}/`이며, 기존에 공개된 정본이 있으면 URL을 바꾸지 않는다.
- 시·도/지역 목록, 지도 핀, 왼쪽 결과 카드, 간단 정보 패널은 같은 장소 ID를 사용해 정본 상세로 연결한다.
- `?place=`, `?category=`, 검색어·필터·지도 이동 상태는 UI 상태다. 정본 페이지·사이트맵·hreflang으로 만들지 않는다.

## 상세페이지 필드

1. 고유한 title·H1·description과 첫 답: 어떤 곳인지, 무엇을 볼 수 있는지, 누구에게 맞는지 쓴다.
2. 장소명: 확인된 한국어 통용명 → 공식 영문명 → 한국 현지 표기 순서로 첫 이름 블록에 한 번 표시한다. 같은 이름을 반복하지 않는다.
3. 주소: 확인된 도로명 주소와 출처를 표시한다. 좌표만으로 주소를 만들어내지 않는다.
4. 요금: 성인·어린이·무료 구역·유료 시설·특별전·예약 조건을 구분하고 통화·적용일·확인일을 기록한다.
5. 운영: 기본 영업시간·휴관일·기간별 예외를 구분한다. 확인되지 않은 시간을 상시 운영으로 쓰지 않는다.
6. 가는 길: 출발지·노선·방향·하차·환승·도보 순서를 실제 공식 근거와 함께 쓴다.
7. 장소 고유 볼거리·방문 선택 기준·필요한 계절·예약·보행 조건을 근거와 함께 쓴다. 방문 경험·인기 순위·최고 표현을 지어내지 않는다.
8. 입장권 CTA: 해당 시설의 입장권이고 검증된 CPA가 있을 때만 `입장권 예약하기`를 표시한다. 투어·교통 상품은 입장권으로 표시하지 않으며 상품이 없으면 버튼을 렌더링하지 않는다.
9. FAQ: 장소별 실제 여행자 질문에 필요한 수만 작성한다. 개수를 채우기 위한 질문은 만들지 않는다. 본문·화면 FAQ·FAQ JSON-LD의 답을 일치시킨다.
10. 공식 출처·확인일·관련 권역/시·도·관광지 지도 링크를 표시한다.

## SEO·AEO·GEO 검수

- 첫 HTML에 핵심 답과 내부 링크가 있어야 한다. JavaScript가 실행되어야만 장소명이 생기는 구조를 공개 페이지의 유일한 본문으로 쓰지 않는다.
- title·H1·description·본문·schema가 같은 장소와 질문을 다뤄야 한다. canonical은 정본 URL 하나로 고정한다.
- 공개 언어 원고가 준비된 경우에만 hreflang을 왕복 연결한다. 없는 번역 페이지를 연결하지 않는다.
- 공개 200·index 허용·canonical·본문·사이트맵·내부 링크를 확인한 뒤 배포한다. 제출 접수와 실제 색인·노출·AI 인용은 각각 기록한다.
- 장소명·주소·요금·시간·좌표·CPA 링크는 데이터 원장과 화면의 값을 대조한다. 확인일만 갱신해 오래된 사실을 최신처럼 보이게 하지 않는다.

## 화면 계약

- 관광지 탭을 열면 좌표가 있는 장소는 지도 핀으로 표시하고, 검색/필터 결과는 왼쪽 목록에 장소 사진·명칭·입장료·영업시간·주소를 보여 준다.
- 카드를 클릭하면 같은 장소의 간단 패널을 열고, `상세 보기`는 정본 상세 URL로 이동한다. 핀·카드·검색 결과가 서로 다른 장소를 가리키면 통과하지 않는다.
- 사진은 사용 권리·출처·대체 텍스트를 확인한 자료만 표시한다. 사진이 없으면 빈 이미지나 임의 이미지를 채우지 않는다.
- 모바일에서 긴 지명·주소·버튼이 잘리지 않고 주요 터치 영역이 충분히 커야 한다.

## 기록

장소 ID, 정본 URL, 공식 출처 URL, 확인일, 좌표 근거, 요금·시간 조건, 사진 권리 근거, CPA 발행 URL과 언어·통화, 검수 결과, 보류 사유를 `docs/tourism/attraction-detail-qa/`에 남긴다. 문서 규칙 저장, 원고 완료, 로컬 검증, 배포, 색인, 검색 성과를 같은 완료 상태로 보고하지 않는다.

### 가는 방법과 귀가 계획 — 소유자 2026-10-11 최신 확정


모든 명소의 필수 조사 항목은 자가용과 대중교통이다. 자가용은 출발 기준점·고속도로·IC·국도·진입로·주차장 입구를, 대중교통은 노선·역·출구·버스·하차 정류장·환승·마지막 도보를 공식 근거에서 확인해 작성한다. 도보 시간도 근거가 있을 때만 표시한다. 찾지 못한 항목은 빈 값으로 저장하고 해당 화면을 숨긴다. 공개 문장이나 FAQ를 '정보를 확인하지 못했어요'로 채우지 않는다. 확인된 경로가 있다면 생략하지 않는다.

교통 FAQ는 장소의 입장시간·입장 마감과 귀가 방향 막차를 함께 다룬다. 외곽 명소는 돌아올 막차에서 관람 시간·정류장까지 도보·환승 여유를 거꾸로 계산하도록 안내하고, 오전 방문은 첫차로 도착 가능한지도 확인하도록 한다. 구체적인 첫차·막차 시각과 관람 시간은 공식 자료로 확인된 경우에만 표시한다. 노선 방향·평일/주말·시간표 출처를 구분하며 본문과 FAQ는 같은 사실을 사용한다.

### 계절별 추천과 방문 조건 — 2026-10-11 소유자 추가 확정

계절 안내는 장소의 실내·야외 구성과 실제 방문 목적에 맞춰 작성한다. 실내 명소는 더운 여름이나 추운 겨울, 비 오는 날 실내에서 둘러보는 일정으로 제안할 수 있다. 복합 명소는 실내 전시와 야외 동선을 구분한다. 야외 명소는 근거 있는 봄꽃·신록·단풍·설경과 관람 특징을 연결한다. 장소명만 바꾼 사계절 문장을 복제하지 않는다.

추천 시기뿐 아니라 피하면 좋은 조건도 장소에 맞춰 설명한다. 실제 자료에서 확인되지 않은 냉난방·항상 쌓이는 눈·인기 순위·통제 시각을 단정하지 않는다. 편집 제안은 ‘여름에는 실내 전시를 중심으로 둘러보는 일정으로 추천해요’처럼 안내하고, 공식 운영 조건은 별도로 표시한다. 근거 없는 계절 항목은 숨긴다.

### 카메라와 명소의 양방향 내부 링크 — 2026-10-11 소유자 추가 확정

같은 장소뿐 아니라 실제로 가까운 명소와 카메라도 관계 원장에 등록해 연결할 수 있다. 이 최신 소유자 지시가 이전 ‘같은 촬영 대상만 연결’ 규칙의 장소 간 근접 연결 범위를 확장한다. 정확한 관계를 본문에서 구분한다. 동일 장소의 촬영 대상이 확인되면 ‘{명소} 카메라 보러가기’, 가까운 별도 촬영 장소이면 ‘인근 카메라’ 소제목 아래 실제 카메라명과 위치 관계를 안내한다. 가까이 있다는 이유로 해당 명소가 카메라에 보인다고 주장하지 않는다.

카메라 상세에는 ‘{명소} 상세페이지 보러가기’를 넣는다. cameraId·placeId·양쪽 정본 URL·동일 장소/인근 구분·좌표 또는 공식 근거·거리 의미·관계 설명을 한 원장에서 관리하고, 두 공통 상세 템플릿에서 양방향 렌더한다. 직선거리는 도보 거리나 이동 시간으로 표시하지 않는다. 아직 준비 중이거나 미검수인 상세로 공개 링크를 만들지 않는다.

## 공공누리 이용 조건 — 2026-10-11 소유자 확정

- 공개 사용하는 관광자료·사진은 제1유형(Type1) 또는 제3유형(Type3)만 허용한다. 제2·제4유형 및 이용조건 미확인은 공개 제외하고 상태와 원본 근거를 보존한다.
- 모든 언어·대표사진·갤러리·카드·지도 선택정보에 동일 기준을 적용한다. 제3유형은 자르기·보정·합성·텍스트 덧씌우기 없이 원본 비율 전체를 표시하며 제공기관·출처·이용유형을 표시한다.
- 자료를 다운로드했다는 사실은 사용 허락 확인이 아니다. 이미지마다 공식 이용조건과 실제 장소를 대조한다. rightsConfirmed는 코드 존재가 아니라 Type1/Type3 허용 확인으로 판정한다. 미확인 및 제외 사진을 승인 상태로 자동 변경하지 않는다.

## 여행지·명소 카테고리 — 2026-10-11 소유자 최신 결정

- 여행지·명소와 메인 관광지 탭은 `추천코스`, `체험관광`, `역사관광`, `레저스포츠`, `자연관광`, `문화관광` 6개 공통 분류로 고정한다. 8권역은 지역 축으로 유지한다.
- 음식 자료는 별도 보관하고 삭제하지 않는다. 축제·공연·행사, 숙박, 쇼핑은 여행지·명소에 혼입하지 않는다. 축제는 추후 별도 카테고리로 구현한다.
- 원본 contentTypeId와 lclsSystm1/2/3는 보존한다. 구 3개 API 유형을 공개 필터로 쓰지 않고 최신 관광공사 주제 분류에 근거해 공통 함수로 매핑한다. 미확인 분류는 임의 배정하지 않는다.
- 추천코스는 실제 코스 자료를 별도로 확보한다. 현재 19,078건은 12/14/28 목록이며 추천코스 전량 포함이 아니다. 이전 ‘25 여행코스는 이번 수집 대상이 아니다’는 이 결정으로 변경한다. 자료 확보 전에는 준비 상태로 유지한다.
- 경복궁 placeId `126508`은 기존 원장에 존재하고 lclsSystm1=HS인 역사관광 명소로 유지한다. 엑셀 한 묶음에 없다는 이유로 기존 명소를 누락하거나 삭제하지 않는다.
- 다운로드 범위와 전체 목록·원고·공개 준비 수를 분리해 보고한다. 변경 영향이 없는 기존 검수는 반복하지 않는다. 운영 배포는 포함하지 않는다.


### 대표 사진 수 — 2026-10-11 소유자 최신 결정

명소별 사진은 대표 1장을 기본으로 하고 장소 설명에 필요한 경우만 최대 2장을 사용한다. 다수 사진 갤러리용 수집은 진행하지 않는다. 동일 장소 ID·피사체와 이미지별 공공누리 제1/제3유형 이용조건·출처를 확인한다. 다운로드 완료와 피사체/권리 검수 완료는 구분한다. 이미 검수된 사진은 변경되지 않은 경우 재검수하지 않는다. 제3유형은 원본 비율 전체 표시와 변경 금지 조건을 유지한다.


### 추천코스 구성 장소 사진 예외 — 2026-10-11 소유자 최신 결정

- 추천코스는 여러 방문 장소를 묶은 상세이므로 일반 단일 명소의 대표 1장·총 최대 2장 제한을 적용하지 않는다. 이 예외는 추천코스에만 적용한다.
- 공식 코스의 모든 구성 장소를 확인하고, 코스 및 구성 장소에 해당하는 사진을 다운로드하여 각 장소 설명에 적절하게 배치한다. 코스 전체를 대표사진 1~2장으로 축소하지 않는다. 원본의 장소 순서를 보존하며 사진별 촬영 대상과 해당 정류점의 연결 근거를 기록한다.
- 같은 원본 사진은 한 번만 내려받아 재사용하며 이미 승인된 동일 사진은 재검수하지 않는다. 코스 대표사진만 있고 구성 장소 사진이 없는 상태는 전체 사진 준비 완료가 아니다. 구성 장소별 확보·이용조건·피사체 검수·렌더 상태를 따로 기록한다.
- 제1·제3유형만 사용하고, 다른 장소·중복 사진·이용조건 미확인 또는 금지 사진은 공개하지 않는다. 확보하지 못한 장소 사진은 미확보 사유를 남긴다. 음식점·숙박시설이 원래 코스에 포함된 경우 코스 구성은 보존하되 독립 음식·숙박 명소 카테고리 공개로 확대하지 않는다.
- 모바일은 장소별 사진과 설명을 순서대로 읽을 수 있게 공통 코스 컴포넌트로 관리하고, 제3유형 원본 전체 비율·출처 표시를 유지한다. 검증 완료·운영 배포는 별도 상태다.


추천코스 상세 생성·보강은 [추천코스 고정 템플릿](./KOREAN-RECOMMENDED-COURSE-STANDARD.md)을 반드시 읽고 동일한 공통 렌더로 구현한다. 2026-10-11 소유자 확정: 하단 `명소 리스트`에서 코스 구성 중 실제 등록 명소의 존재하는 정본 상세만 방문 순서대로 초기 HTML 내부 링크를 제공한다.
