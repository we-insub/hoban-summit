# 모하모아 페이지 생성용 SEO·AEO·GEO 컨텍스트 템플릿

**매 작업 시작 전:** [승인본 대조 한국어 검수](REPORT_KOREAN_REVIEW.md)의 필수 목록을 이번 작업에서 처음부터 끝까지 읽습니다. 신규 작성뿐 아니라 원고만 수정·자료 추가·FAQ 갱신에도 적용합니다. 기억·요약·발췌로 대신하지 않고 최종 원고 전체를 승인본과 대조합니다.

분양 분석 리포트는 [리포트 한국어 작성·제작 기준](REPORT_EDITORIAL_STANDARD.md)을 함께 적용한다. 원고 문체 검수, 근거 자료 검증, 시청각 제작·검증 상태를 따로 기록하며 한국어 원고 검수를 먼저 진행한다.

자료·도표·지도·이미지·TTS·영상 생성·재생성 때마다 [소유자 제공 기준 원문 전체](REPORT_OWNER_REFERENCE_FULL.md)와 리포트 작성 기준 전체를 다시 읽는다. 요약·발췌로 대신하지 않으며 원문과 기존 원고·자료를 임의로 함축·요약·삭제하지 않는다. 작업 명세에 읽은 문서, 적용 항목, 해당 없음 항목과 사유를 기록한다.

모하모아의 새 공개 페이지 및 기존 페이지·메타·공통 렌더러·분석 코드를 생성·수정·유지보수할 때 이 문서를 복사해 작업 명세로 채운다. `[ ]`는 실제 조사 결과로 대체한다. 모르면 `확인 필요`, 적용되지 않으면 `해당 없음`으로 남긴다. 검색 노출·순위·AI 인용을 보장하는 문서가 아니다.

리포트의 상위·관련·단지 상세·비용 연결 및 공개 색인 정책은 [리포트 내부 연결·색인 운영 기준](REPORT_INTERNAL_LINKING.md)을 함께 적용한다.

## 2. 사실·출처·제한

공식 분양·모집 자료, 지자체·공공기관 공고, 운영 주체의 공식 안내, 현재 사이트의 데이터와 기존 페이지를 확인한다. 다른 중개·홍보 사이트의 문구를 원출처처럼 사용하지 않는다. 문서·공고의 작성일과 **실제 확인일**을 구분한다.

| 본문에 쓸 사실 | 공식 근거 URL·자료명 | 자료 기준일 / 실제 확인일 | 적용 단지·블록·지역·조건 | 본문 위치 |
|---|---|---|---|---|
| [예: 단지 규모] | [URL] | [YYYY-MM-DD / YYYY-MM-DD] | [총 세대인지 공급 물량인지] | [위치] |
| [사실] | [URL] | [날짜] | [범위·예외] | [위치] |

- **편집 설명·비교:** [어떤 공식 사실을 어떤 기준으로 비교하거나 설명하는가]
- **확인하지 못한 정보:** [분양가, 현재 잔여 물량, 계약 혜택, 견본주택 운영·예약 등]
- **쓰지 않을 주장:** [근거 없는 상위·최고·독점, 직접 방문·상담 경험, 예상 수익·미래 가격 등]
- **변경 가능성과 재확인 계기:** [공고 수정, 접수 종료, 가격표 변경, 현장 운영 변경 등]
- **독자가 재확인할 공식 경로:** [URL·문의처; 모하모아 자체 상담과 구분]

시점에 따라 바뀌는 수치를 표시할 때는 날짜와 적용 조건을 본문 가까이에 둔다. 자료가 오래됐거나 출처가 끊겼으면 현재 사실로 단정하지 않는다. 단지명·블록·행정구역이 다른 자료를 합치지 않는다.

## 3. 검색 의도와 SEO

| 항목 | 기록 |
|---|---|
| 대표 검색 의도 | [방문 전 확인 / 분양 정보 / 청약 자격 / 비교 / 비용 계산 등] |
| 핵심 검색어 | [페이지가 실제로 답할 한 표현] |
| 관련 표현·질문 | [조사된 표현과 이 페이지에서 답할 내용; 개수 제한 없음] |
| title / H1 / meta description | [각각 실제 본문과 맞는 자연스러운 문장] |
| canonical | [실제 정본 URL] |
| 기존 URL·리디렉션 | [변경 이유와 이전 URL, 또는 해당 없음] |
| 내부 링크 | [상위 목록, 관련 단지·가이드·계산기 / 연결 이유] |
| 다음 행동 | [공식 정보 확인 / 실제로 제공되는 모하모아 상담·안내 등] |

### 상세 페이지 검색어 조사

1. 해당 단지의 공식 명칭, 일반적인 검색 표기, 광주·전남의 실제 행정구역, `모델하우스`·`견본주택` 등 동의어를 구분한다. `챔피언스시티 모델하우스`처럼 검색어가 특정 단지를 뜻하면 그 단지의 정보만 답한다.
2. Google Trends에서 **한국어 검색어·대한민국·최근 12개월**을 기본으로 관련 검색어의 `인기`와 `급상승`을 확인한다. 입력한 **검색어**와 여러 표현을 묶는 **주제**를 구분한다. 다른 언어 페이지는 실제 언어·대상 국가에 맞춰 설정한다.
3. Trends 자료가 부족하면 같은 언어·지역의 Google 자동완성·관련 검색어·관련 질문을 확인한다. 한국어 페이지는 네이버 검색 제안도 확인한다. 제안은 검색량이나 Trends 수치로 표기하지 않는다.
4. 독자의 실제 질문에 도움이 되는 표현만 채택한다. 중복 의미는 합치고, 검색량·순위·인기도를 임의로 만들지 않는다. 접근이 안 되면 `조사 불가`와 이유를 남긴다.

| 검색 조사 | 기록 |
|---|---|
| 대상 URL·주제 | [URL·단지 또는 페이지 질문] |
| 입력 표현·검색어/주제 | [원문·선택 유형] |
| 언어·국가·기간·조사일 | [설정, 12개월 시작·종료일, YYYY-MM-DD] |
| 근거 | [Trends 인기/급상승, Google 제안, 네이버 제안 중 어디인지 / 확인 가능한 URL·자료] |
| 채택 표현·이유 | [실제로 답할 질문과 본문 위치] |

제목·H1·메타 설명·첫 문단은 같은 주제를 말하되 문장을 기계적으로 반복하지 않는다. 핵심 답은 클릭 후에만 드러나는 UI가 아니라 색인 가능한 본문에 쓴다. 기존 슬러그·canonical·추적값을 보존하고, 언어별 URL이나 `hreflang`은 실제 다국어 페이지가 있을 때만 관리한다. 검색어를 끼워 넣는 문장이나 이름만 다른 중복 랜딩 페이지를 만들지 않는다.

## 4. AEO: 독자의 질문에 직접 답하기

아파트 상세·비용 안내·리포트는 공통 `BookingFaq`에 해당 아파트명을 전달해 고정 예약 질문·답변·혼잡 시 약 10분 안내 조건을 함께 표시한다. 문구는 [리포트 작성 기준](REPORT_EDITORIAL_STANDARD.md#전-페이지-고정-예약-faq)의 소유자 정본을 따른다.

리포트에는 해당 본문을 근거로 한 글별 질문·직접 답변도 추가한다. 고정 예약 FAQ만으로 대신하지 않는다. 확인된 정보는 소제목·첫 문장에 실제 답을 제시하며, 독자에게 ‘확인해야 한다’는 설명만 남기지 않는다.

| 질문 | 짧은 직접 답 | 공식 근거·실제 확인일·조건 | 공개 본문 위치 |
|---|---|---|---|
| [예: 견본주택은 어디인가요?] | [확인된 위치 또는 공식 확인 경로] | [URL / YYYY-MM-DD / 적용 블록] | [본문·FAQ] |
| [질문] | [1~2문장] | [출처·날짜·예외] | [위치] |

- 이동·방문·계약 판단에 중요한 답은 본문에서 먼저 설명한다. FAQ는 추가 질문이 실제로 있을 때만 만든다. 개수를 채우기 위해 질문을 늘리지 않는다.
- FAQ 및 구조화 데이터의 질문·답은 독자가 보는 문장과 일치해야 한다. 현재 분양가·잔여 물량·계약 가능 여부처럼 확인되지 않은 사실을 답으로 만들지 않는다.
- 사실 안내에는 출처 링크·실제 확인일·적용 범위를 가까이 둔다. `AI 최적화` 문구나 인용 보장 문구를 게시하지 않는다.
- 공식 분양·방문 안내와 모하모아의 상담·예약 신청은 링크 문구로 구분한다. 실제로 제공하지 않는 예약, 링크, 제휴 상품이나 추적값을 만들지 않는다. 광고·제휴 관계가 있는 외부 링크에만 해당 고지와 적절한 `rel` 속성을 적용한다.

## 5. GEO: 인용 가능한 근거와 자체 설명

| 답변에 쓸 주장 | 공식 근거 URL | 확인일 | 적용 범위·예외 | 모하모아의 비교 기준·이유 | 공개 위치 |
|---|---|---|---|---|---|
| [구체적 사실] | [URL] | [날짜] | [단지·블록·공고 조건] | [비교하지 않으면 해당 없음] | [본문 위치] |

자료의 사실과 모하모아의 해석·비교를 구분한다. 비교한다면 비교 대상과 기준을 명시한다. 독립적으로 읽힌 문단도 어느 단지·시점·조건인지 알 수 있게 쓰되 단지명을 불필요하게 반복하지 않는다. 직접 방문하거나 취재하지 않았다면 그렇게 보이는 표현을 피한다. 작업 표에 적은 근거·조건이 **공개 본문에도** 전달돼야 한다.

- [ ] 대표 동적 페이지의 렌더 DOM에서도 head 배치·값·개수를 확인했다. 변경 전후 HTML/DOM과 User-Agent를 저장했다.

- [ ] 현재 운영 버전·소스 SHA와 이번 변경만 분리한 검증 소스·배포 산출물을 연결했다. sitemap 전체 구조 검사와 비공개/404 제외, 전체 원고 감수 범위를 구분했다.


- [ ] 독자의 질문에 첫 문단에서 확인된 사실로 직접 답하고, 초기 HTML에도 답이 있다.
- [ ] 단지명·블록·주소·세대수·가격·날짜·지역 정보의 근거와 적용 범위를 확인했다.
- [ ] 출처 링크, 문서 기준일, **실제 확인일**이 필요한 사실 가까이에 보인다.
- [ ] 공식 사실, 모하모아의 비교·설명, 상담·광고 문구를 구분했다.
- [ ] `title`, H1, 메타 설명, 본문, FAQ, 구조화 데이터가 같은 사실을 말한다.
- [ ] URL, canonical, robots, 사이트맵, 내부 링크와 기존 리디렉션을 확인했다. 실제 다국어 페이지가 있다면 `hreflang`도 확인했다.
- [ ] 모바일에서 제목·첫 답·출처·CTA를 읽고 사용할 수 있다.
- [ ] 한국어 제목·본문·카드·버튼·FAQ를 직접 읽고 부자연스러운 표현과 근거 없는 단정을 고쳤다. 다른 공개 언어도 각각 검수했다.
- [ ] 코드 변경 시 관련 타입 검사·빌드·동작 검사를 했다. 로컬 검증, 배포, 운영 URL 확인을 구분해 기록했다.
- [ ] 성과 측정이 필요하면 URL, 기준일, 검색어·질문, 관찰 지표를 정했다. 순위·색인·AI 인용을 보장하지 않았다.
