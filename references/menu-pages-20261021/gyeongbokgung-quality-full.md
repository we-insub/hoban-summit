# 관광지·명소 설명 깊이와 가독성 검수표

## 2026-10-13 소유자 확정 — 한국어·다국어 문장 기준

[자연스러운 여행 글 기준](../writing/VISITOR-EXPERIENCE-WRITING-STANDARD.md)과 시로코 전후 예문을 필수 적용한다. 경복궁의 설명 깊이를 유지하면서 확인된 사실을 구체적인 관찰·활동·동행·방문 준비로 연결한다. 시설 나열이나 해요체 어미만으로 충분 판정하지 않는다. 모든 지원 시장도 같은 방문 매력과 정보 깊이를 각 언어로 자연스럽게 작성·실독 검수한다. 완료된 정상 사실·사진·교통은 재검수하지 않고 새 기준의 부족한 문장만 수정한다. 문체 판정은 8개 검증의 content 안에 기록한다.

## 2026-10-13 소유자 추가 — Muse 보강·반환 고정 프롬프트

Muse에는 이 단계에서 검수가 아니라 기존 검증 자료를 사용한 원고 보강 작성을 맡긴다. 정상 사실·사진의 재조사·재검수나 정상 원고 전체 재작성은 요청하지 않는다. 저장 후 재독은 파일 저장 확인이며 검수 완료 선언이 아니다.

- 꼭 볼 것: `제목 — 확인된 특징, 왜 눈여겨볼 만한지, 방문자가 무엇을 살펴보면 좋은지`로 설명한다. 명칭 재서술·시설 나열 또는 “유명해요”, “볼 수 있어요”만으로 끝내지 않는다.
- 이런 분께 추천해요: `추천 대상 — 해당 대상이 이 장소에서 무엇을 보고 즐기며 왜 맞는지`로 쓴다. 역사 관심자·아이 동반 가족 등 장소에 맞는 추천은 편집 제안이며, 미확인 체험·어린이 시설·무장애·계단 조건은 만들지 않는다.
- 자연스러운 해요체를 유지하고 과장 찬사·구역 간 같은 문장 복제·방문정보 표 반복으로 분량을 채우지 않는다. 장소 규모에 맞는 깊이를 적용하며 최소 글자 수를 강제하지 않는다.
- HTML/Markdown 없이 `제목 — 설명`으로 저장한다. 공통 CSS가 볼거리 제목 및 추천 대상을 강조하고 설명은 일반 글씨로 표시한다.
- 앞으로 작성하는 원고와 현재 보강이 필요한 항목에 적용한다. 이미 완료된 정상 항목의 전수 재검수 지시로 사용하지 않는다.

반환 프롬프트에도 다음 문구를 함께 넣는다: “반환된 실패 필드만 수정하세요. 그 구역에 왜 눈여겨볼 만한지 또는 추천 대상에게 왜 맞는지가 부족하면 기존 검증 자료로 해당 설명도 함께 보강하세요. 다른 정상 원고는 다시 쓰거나 검수하지 마세요. 명칭 나열·유명해요만으로 끝내지 말고 자연스러운 해요체로 구체적인 방문 이유를 연결하세요. 확인되지 않은 사실은 만들지 마세요. 이번 단계는 원고 작성만 수행하고 변경값을 저장해 제출하세요.”

CSS·링크·중앙 반영 등의 기술 결함은 해당 기술 담당에게 반환한다. 정상 본문이 이미 충분하면 기술 반환을 이유로 본문 보강이나 재검수를 요구하지 않는다.

확정: 2026-10-12 소유자 승인. 기준 시안: 가금철교 문화공원 `/kr/attractions/3482667/`의 보강 원고와 추천 대상 강조 화면.

이 문서는 관광지 상세 표준의 추가 검수 기준이다. 새 공통 틀을 복제하지 않고 기존 데이터 로더·Astro 템플릿·CSS에 적용한다. 추천코스는 자체 고정 표준을 유지하고 구성 명소의 문장·추천 이유에 이 기준을 적용한다.

## 1. 유지할 말투와 보강 목적

현재 승인된 자연스러운 해요체를 유지한다. 쉬운 단어, 짧고 연결되는 문장으로 안내하고, 분량을 늘리기 위해 딱딱한 보고체·홍보문·내부 작업 설명을 넣지 않는다. 어미 일괄 치환은 감수가 아니다.

충분한 설명은 '어떤 곳인가 → 무엇을 보고 할 수 있나 → 누구에게 왜 맞나 → 어떻게 방문을 준비하나'에 답하는 내용이다. 모든 명소를 같은 글자 수·문단 수·FAQ 수로 늘리지 않는다. 작은 도심 공원은 산책과 지역 일정, 산은 산행 구간과 준비, 박물관은 전시·체험, 궁궐은 관람·해설 중심으로 설명한다.

표의 값을 문장으로 반복하거나 같은 사실을 볼거리·추천·계절·FAQ에서 되풀이하는 것으로 보강하지 않는다. FAQ에서 중요한 값을 짧게 다시 답하는 것은 가능하지만 질문에 맞는 직접 답이 있어야 한다. 각 구역에 별도의 역할을 준다.

## 2. 공통 출력 계약

- 대표 사진·명소명·첫 소개 → 기본 방문 정보 → 고유 볼거리 → 추천 대상과 이유 → 계절별 방문 → 필요한 동반 안내 → 관람 동선 → 확인된 가는 길·주차 → 방문 전 확인 → FAQ·공식 출처 순서를 유지한다. 근거·의미가 없는 구역은 숨긴다.
- 볼거리: `제목 — 설명`을 저장하고 공통 `splitTitleDesc`로 소제목과 본문을 분리한다. 단순 명칭 뒤에 '볼 수 있어요'만 붙이는 대신 볼거리의 특징이나 방문 목적과의 관계를 설명한다.
- 추천 대상: `추천 대상 — 그 장소에 맞는 이유`로 저장한다. 추천 대상만 `<strong>`으로 굵게, 이유는 일반 글씨로 출력한다. 데이터에 HTML·Markdown 굵게 기호를 넣지 않는다. 현재 공통 분리 함수에 맞춰 대상 제목은 간결하게 쓴다.
- 구현 정본: `src/pages/kr/attractions/[placeId].astro`, `src/styles/attraction-detail.css`, `src/lib/attractions/display-format.ts`. 승인된 카드·소제목·추천 영역·안내 상자·FAQ 스타일을 사용하고 페이지별 인라인 CSS를 복제하지 않는다.
- 운영시간·휴무일·입장료 등 기본 방문 정보의 주된 값은 같은 본문 크기·색·행간으로 표시한다. `※ 전시 및 행사별로 상이함`처럼 해당 항목의 유일한 안내도 주된 값이며 작은 보조 글씨로 낮추지 않는다. 별도의 예외/부가 설명이 있을 때만 보조 스타일을 사용한다. PC와 모바일 모두 값 앞 빈 줄을 넣지 않는다. 경복궁의 월별 시간표나 특정 시설 조건을 복제하는 규칙이 아니다.
- 위 규칙의 화면 검수는 눈으로 보는 것과 실제 계산된 CSS를 함께 확인한다. 같은 화면 폭에서 운영시간·휴무일·입장료의 주된 값의 `font-size`, `color`, `line-height`를 대조하고, 각 값의 시작 위치에 빈 줄이나 단독 안내용 목록의 불필요한 위 간격이 없는지 확인한다. `※`로 시작한다는 이유만으로 주된 값을 보조 설명으로 분류하지 않는다. 동일 안내 내용인데 스타일만 다르거나 교통 구역이 제출됐는데 최종 로컬 화면에 없으면 fail이며, 발견 후 해당 차원만 수정·재검증한다.
- 운영시간이 실제로 월·계절에 따라 달라지고 공식 근거가 있는 경우에만 시기별 행으로 나눈다. 연중 같은 시간은 한 행, 상시 개방은 상시 개방으로 안내한다. 모든 장소에 월별 시간표·입장 마감·사계절 구역을 강제하지 않는다. 요금은 실제 대상별 구분이 있을 때, 주차요금은 실제 차종별 구분이 있을 때 행으로 나누고 휴무 예외는 보조 문장으로 표시한다. PC는 항목명/값을 나누고 모바일은 항목명 아래 값이 읽히도록 한다.
- PC 1440 / 모바일 390에서 제목과 이유의 굵기 구분, 자연스러운 줄바꿈, 긴 주소·숫자·버튼, 내용 가로 넘침을 확인한다. 잘림이나 줄 수 제한으로 설명을 숨기지 않는다.

## 3. 장소별 보강 판단

첫 소개는 장소 정체와 방문 선택을 돕는다. 상세 연혁은 필요할 때 볼거리 설명으로 옮긴다. 추천 대상에는 그 장소의 시설·풍경·활동을 근거로 이유를 덧붙인다.

계절은 실내·야외 구성과 방문 목적에 맞춘다. 근거 없는 사계절 복제, 특정 개화일·설경·냉난방 단정은 금지한다. 날씨에 따른 일정 제안은 편집 제안으로 자연스럽게 쓰고 매 구역에 주의 문장을 반복하지 않는다.

관람 동선은 확인된 장소 구성과 순서를 사용한다. 공식 코스·거리·시간이 없으면 선택형 둘러보기 제안으로 쓰고 실제 공간 배치·연결·소요 시간을 만들어내지 않는다. 아이·부모님·유모차 안내도 장소별 확인 근거가 있을 때만 시설·계단·이동 조건을 단정한다.

자가용·대중교통은 기본 조사 항목이다. 확인된 IC·국도·역·출구·정류장·도보 정보를 누락하지 않는다. 조사했으나 찾지 못한 정보와 아직 조사하지 않은 상태를 구분하고, 근거 없는 노선·시간을 채우지 않는다. 공원에 주차가 없다는 안내를 교통 경로 조사 완료로 계산하지 않는다. 첫차·막차·관람·입장마감은 필요한 장소에서 확인된 조건으로 설명한다.

FAQ는 방문자의 질문에 바로 답한다. 표를 늘리는 대신 볼거리 선택, 방문 시기, 실제 접근과 이용 조건 등 장소별 필요한 질문을 다룬다. 연관검색어는 실제 조사 근거를 보존하며 임의 검색량이나 SEO 문구를 만들지 않는다.

## 5. 이미 완료된 검수 제외와 담당 계약

이미 검수 완료된 사실·사진·문체 항목은 큐에서 제외하고 재검수·새 완료 집계하지 않는다. 이번에 승인된 설명 깊이/표현 기준이 기존 증거에 포함돼 있으면 그대로 인정한다. 새 기준의 미확인 부분이 있다면 그 추가 차원이나 실제 결함만 검토·보강한다. 정상 문장 전체 재작성·정상 사진 재열람은 하지 않는다. 수정한 경우 영향 필드와 해당 렌더만 확인한다.

채팅 간 병렬, 채팅 안 장소 한 건 검수·실제 Mac 저장·재독 후 다음 ID 직렬. 작성 담당은 독립 인계 파일, 검수 담당은 자기 Q번호 결과만 수정하며 정본·공통 구현·공개 manifest는 중앙 통합한다.

기존 결과 스키마를 유지하고 필요할 때 `visitorValueQA`를 추가한다: 기준 문서/버전, 상태, 실제 확인한 항목, 기완료 제외 근거, 보강 필요 필드, 원고/출처 SHA. 문서 저장만으로 과거 결과를 pass로 채우지 않는다. 미반영 patch 또는 render pending이면 `readyBeforeDeploy=false`다.

## 6. 승인 시안 예시와 한계
